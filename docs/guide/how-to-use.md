这份文档不是写给别人看的教程，是写给"未来的你"的操作单。所以它的结构和普通文档站不太一样。

## 每页的固定结构

软件类页面永远是这七段，顺序不变：

| 段落 | 里面是什么 |
| --- | --- |
| 定位 | 一句话说清它是什么、为什么装它 |
| 干什么用 | 你实际会用它做什么 |
| 装 | Windows / macOS / Linux 三个分栏，正反例都有 |
| 验证 | 装完跑什么命令能确认成功 |
| 配置在哪 | 配置文件路径、目录结构 |
| 备份与还原 | 哪些目录要拷、怎么拷回来 |
| 官方链接 | 官网、文档、仓库、包管理器页面 |

**为什么固定结构**：换机的时候人是急的，不想学新的阅读方式。固定结构意味着你知道"验证命令"永远在第三节，
不用每次找。

## 三种页面类型

**顺序页**（[换机顺序](/guide/order)）—— 告诉你先做什么后做什么。只在真正要做一遍完整迁移时看。

**条目页**（[Node.js](/env/nodejs)、[Git](/env/git) 等）—— 单个东西的全部信息。装某一个软件时看。

**清单页**（[备份清单](/migrate/backup)、[版本快照](/guide/snapshot)）—— 横向对比多个东西。做决策时看。

## 页面上的标记

| 标记 | 含义 |
| --- | --- |
| 灰色小标签（如 `24.21.0`） | 版本号，等宽字体，可以直接抄 |
| 蓝色左边线 | 提示、经验、值得注意的做法 |
| 橙色左边线 | 警告，做了会出问题 |
| `最近核对 2026-10-31` | 这一页的命令和链接在这天实查过 |

## 关于"命令能不能直接抄"

**能，但要看清平台。** 所有命令都在分栏里标了平台，Windows 用 PowerShell 语法，
macOS / Linux 用 bash 语法。两者不通用，比如 `;` 在 PowerShell 里是分隔符，在 bash 里也是，
但 `&&` 在 PowerShell 5.1 里不能用（7.x 才行）。

## 这份文档不写什么

明确不写的东西，免得你以后到处找：

- **真实密钥、订阅链接、API Key** —— 一律占位符。原因见 [密钥与脱敏](/migrate/secrets)
- **具体项目的配置** —— 这里是环境手册，不管某个 repo 怎么配
- **教程性质的原理解释** —— 只写"怎么做"和"为什么这样做会出问题"

## 定期维护

内容会过期。维护方式：

1. 改动任何一页后，更新页内和 `site.config.mts` 的 `lastChecked`
2. skills 清单是脚本生成的，重跑 `pnpm skills` 就能刷新
3. 不确定的链接先留着，下次核对时再删
