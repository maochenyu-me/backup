# 换机手册：Teek 文档风主题迁移设计

状态：用户已于 2026-11-01 确认设计，进入实施计划阶段。本文不是实施完成报告；实施计划确认前不安装依赖、不改主题入口与页面代码。

## 1. 目标与范围

用户希望为现有 VitePress 换机手册选择并接入仍在维护、功能完善的主题，改善样式与 UI。已同意以 Teek 为选型方向，采用文档风而不是博客风。

本次目标是让首页、导航与文档正文形成一致的视觉系统，同时保留安装顺序、验证命令、版本表和配置路径的快速查阅能力。

不改写安装教程，不新增评论、阅读统计、登录、博客归档、壁纸或外部字体，不升级 VitePress 到 2.x，不变更既有文档 URL，不部署、不推送。

## 2. 选型与版本依据

- 推荐：`vitepress-theme-teek`，文档风，精简功能。
- 本轮核对的 npm 最新版为 `1.6.2`，发布时间 2026-07-25，peerDependencies 为 `vitepress: ^1.6.4`。实施时锁定该已核对版本，而非无约束追踪 latest。
- 当前项目 VitePress 为 1.6.4，保持不变。若依赖解析发现其他冲突，先报告，不借机扩大升级范围。
- Teek 仓库最近核对到 2026-09-04 的文档修复，核心包最近核对到 2026-07-25 的修复。不能承诺未来维护频率。
- Sugarat 的近期维护更频繁，但博客相关依赖更多；Pure 以文章归档为核心，不如 Teek 文档风贴合本项目。

## 3. 当前结构与兼容边界

当前 `theme/index.ts` 扩展 VitePress 默认主题，`Layout.vue` 使用默认布局的 `home-hero-before` 插槽挂载 `Home.vue`。首页 Markdown 仅声明 `layout: home`。

现有四份 CSS 各有职责：

- `tokens.css`：信号青品牌色、明暗色板、系统字体与 VitePress 变量映射。
- `components.css`：胶片头、版本徽标、定义列表、时间线，以及部分全局正文覆盖。
- `home.css`：自定义首页排版。
- `home-extra.css`：隐藏默认 Hero、首页容器补丁。

主要风险不是 Markdown 迁移，而是默认布局包装方式与全局 CSS 叠加。旧文件中全局隐藏 `.VPHero` / `.VPFeatures`、宽度与间距覆盖，不能不加区分地继续加载。

当前工作区还有上一任务的 DSH / DSH-TUI 文档与导航修改。实施必须保留这些未提交改动，不执行整体回退或覆盖配置文件。

## 4. 采用方案与替代方案

采用「Teek 负责框架布局 + 本站保留少量业务组件」。它比整站复制博客模板更符合查阅场景，也比继续全面覆盖默认主题更能复用主题后续维护。

替代方案一：只继续美化默认主题，迁移风险最低，但不满足本次接入成熟主题的方向。

替代方案二：全量采用 Teek 博客首页，展示能力强，但会用文章流替代换机时间线，并引入大量不需要的界面元素，不采用。

## 5. 信息架构与页面设计

### 5.1 全站框架

保留站名「换机手册」、顶栏入口、各分区人工侧栏和本页目录。Teek 负责文档框架与基础交互，不启用自动侧栏、自动永久链接或自动修改 frontmatter 的插件能力。

保留现有 local search、代码分组图标、中文界面、页脚与明暗切换。搜索索引不得出现迁移设计及实施计划。

### 5.2 首页

不使用文章时间流。保留现有自定义首页的三个任务入口和八步换机清单，继续从 `site.config.mts` 读取站名、定位文案、核对日期与步骤。

视觉上保留左侧导语、右侧换机步骤的桌面双栏，窄屏按导语、入口、步骤的顺序纵向排列。下方保留软件版本速查表与安全提示，不改变现有表格事实。

在主题允许的首页扩展点挂载本站首页组件；若布局插槽无法兼容，改为一个单一、明确的自定义首页插槽适配层，不叠加两个布局或隐藏第二套首页来凑效果。

### 5.3 文档页

继续保留软件页胶片头、版本徽标、配置定义列表和换机时间线；只调整外观，不批量改正文。

正文保留清楚的 H1 / H2 / H3 层级。避免 Teek 自动标题与现有胶片头造成重复标题。面包屑可保留，但作者、发布时间、阅读时长、阅读量、评论和赞赏不显示。

代码块保留语言标签、复制按钮、平台分组和高亮，不默认折叠安装步骤中的命令。长代码只在代码块内横向滚动。宽表格允许自身滚动，页面本身不得横向溢出。

## 6. 视觉规则

- 延续青色作为唯一主强调色，保持与当前站点辨识度的连续性。
- 浅色采用冷灰背景与白色内容面；深色采用深灰内容面，避免大面积纯黑与低对比灰字。
- 使用系统中文字体和系统等宽字体，不下载 Web 字体。
- 以留白、标题层级、浅边框和适度圆角区分内容；允许入口和步骤区域使用轻量容器，不堆叠投影、不使用玻璃拟态或背景渐变。
- 普通文档正文以约 16px 起步、足够行高为基准；正文链接可辨认，键盘焦点可见。
- 保留标准明暗模式切换；关闭非必要动画，并尊重 `prefers-reduced-motion`。
- 不将 Teek 所有默认样式重新覆盖成旧主题；本站 CSS 只负责业务组件、品牌变量及经验证的兼容修正。

`DESIGN.md` 中「拒绝第三方主题」「全站零圆角」等旧决定将在实施时由本方案替代；未涉及的内容、安全和信息架构原则继续有效。设计尚未确认前不改写该文件。

本文和后续计划位于 VitePress 源目录内；实施时必须通过站点源文件排除配置将 `superpowers/**` 排除，避免进入构建、搜索、站点地图与公开产物。

具体 Teek API 名称、开关默认值和导入路径必须在编写实施计划时查对应 1.6.2 文档或包源码确认，不能把选型阶段的概念性说明直接当作代码。

## 8. 验证与验收

实施时先记录当前构建与链接基线，再进行以下验证；本设计阶段不声称这些已经通过。

1. `pnpm build` 成功，`pnpm verify:links` 无新增坏链，`git diff --check` 通过。
2. 关键页面：首页、换机顺序、Node.js、DSH、DSH-TUI、备份清单。逐一检查顶部导航、侧栏、目录、正文、代码与表格。
3. 浏览器在桌面约 1440px 与手机 390px 视口检查浅色、深色模式；无重复首页、重复标题、被覆盖按钮、页面级横向溢出。
4. 实际操作侧栏、目录跳转、local search（含 DSH-TUI）、代码分组、复制按钮、明暗切换、移动端菜单与内部链接。复制结果需与源命令一致。
5. 检查控制台无新增应用错误；主题资源无新增 404；无新增评论、统计、外部字体等请求。浏览器扩展注入的错误单独说明。
6. 使用临时项目 base 验证嵌套路径部署，确保导航、图标、搜索和资源可用；验证 `DOCS_CLEAN_URLS=false` 的构建与链接，不把 HTTP 预览等同于完整 file:// 离线可用证明。
7. 生成站点中不存在设计文档和计划页；原有 Markdown 路径及安装内容未被自动重写。

完成标准：界面确实采用统一的 Teek 文档风，首页仍是换机执行入口，已有内容和部署选项不回退。不能仅凭安装依赖或构建成功判定 UI 完成。

## 9. 风险与回退

- 布局或 CSS 冲突：从薄适配层及旧补丁清理解决，不复制整套 Teek 源码。
- 插件副作用：关闭自动 frontmatter、永久链接及侧栏生成，检查内容文件 diff，出现非预期写入即停止追查。
- 新依赖与旧 group-icons 重复：仅保留一条插件注册链，以构建和浏览器行为为准。
- 备份与回退以本次改动的逐文件差异为边界；不得回退上一任务未提交的 DSH 文档。
- 不满足核心阅读或部署验收时，恢复本次主题接入相关文件，保留已有安装教程。
